05Una métrica, bien documentada

Tres números distintospasan a ser uno.

94,1 · 96,0 · 92,4 → 92,4 %. La ficha dice por qué.

OTIF %Ficha de la métrica
Qué es
Pedidos que llegan a tiempo y completos, sobre los pedidos entregados.
Grain
Un pedido, no una línea: por línea daba 96,0 %; por pedido, 92,4 %.
Filtros
Solo pedidos entregados en las 3 bodegas; costos de transporte, fuera.
Lógica
«A tiempo» = recibido por el cliente en la fecha prometida. Manda la definición de Servicio al cliente, no la de Logística.
Dueño y ritmo
Gerencia de operaciones · se mira cada lunes · meta 94 %.
OTIF % = DIVIDE ( [Pedidos OTIF], [Pedidos entregados] )
dbt YAMLTMDL ///Copilot lee 200 caracteres
06Dónde vive

Junto al código,no en una wiki aparte.

Se escribe una vez y viaja: de dbt a BigQuery, y del modelo a quien pregunta.

1 · dbtDescripciones y tests en el YAML
models:
  - name: fct_despachos
    description: >
      Una fila = una línea de pedido despachada.
    columns:
      - name: pedido_id
        description: Pedido del cliente.
        data_tests: [not_null]
persist_docs → BigQuery
2 · BigQueryLa tabla y cada columna, descritas
  • Descripción de tabla y columna
  • Knowledge Catalog · glosario
  • Linaje por columna
3 · Power BILa medida, descrita en TMDL
/// Pedidos a tiempo y completos ÷ pedidos
/// entregados. Grain: pedido. Dueño: Operaciones.
measure 'OTIF %' =
    DIVIDE ( [Pedidos OTIF], [Pedidos entregados] )
    formatString: 0.0%
    displayFolder: Servicio
PBIP en Git · Copilot lo lee
07Con IA, y cómo lo valido

La IA escribe rápido.Yo respondo por cada palabra.

  1. 1

    La IA escribe el borrador

    Claude Code lee el repo; el Power BI Authoring MCP server escribe las descripciones del modelo.

  2. 2

    Lo comparo con el código

    Fórmula, grain y filtros, uno por uno. Si no calza, se corrige.

  3. 3

    Un test avisa lo que falta

    dbt-project-evaluator y la regla «Visible objects with no description».

  4. 4

    Se revisa en Git

    Cada cambio de documentación pasa por el diff del pull request.

✕ Nunca datos personales en el chatuna descripción sin leer la medidaque una IA revise a otra: no coincide con el juicio humano

08Errores comunes

Documentar males peor que no documentar.

  • ✕ Una wiki aparte que nadie actualiza→✓ Junto al código, revisada en cada cambio
  • ✕ La misma métrica definida en cada tablero→✓ Una vez, en el modelo
  • ✕ Documentarlo todo→✓ Lo que se usa, según el riesgo
  • ✕ Aceptar lo que escribe la IA→✓ Revisión humana contra el código
  • ✕ Describir el cómo→✓ Explicar el porqué y la excepción
09Cómo sé que terminé

Se entiende sin mí.Y la IA responde lo mismo que el tablero.

  1. ✓
    Cada medida visible tiene descripciónY un test lo comprueba en cada cambio.
  2. ✓
    Cada métrica tiene dueño y fecha de revisiónSi nadie la revisa, se marca.
  3. ✓
    Las decisiones están en la bitácoraCon la alternativa que se descartó.
  4. ✓
    Alguien nuevo responde «¿qué es OTIF?» sin preguntarmeNi a mí ni a la IA: lo lee.
